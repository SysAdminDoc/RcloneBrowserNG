# Blocked Roadmap: RcloneBrowserNG

Only work that needs the maintainer's own accounts, identity, money or say-so, or a release someone else hasn't shipped yet, lives here. Everything else is in `ROADMAP.md`. The line under each entry says what was tried and when.

---

## P1 Security

- [ ] P1 Rebuild releases on Qt 6.12.1
  Blocked on: The Qt Company publishing 6.12.1 to download.qt.io. On 2026-11-15 the `qt6_6120` repository was the only 6.12 entry under `online/qtsdkrepository/windows_x86/desktop/`, and there was no `qt6_6121`.
  Why: CVE-2026-116337 (Qt Network memory exhaustion on a crafted HTTP response) is fixed only in 6.12.1 and 6.8.10. The app reaches it through the remote daemon client and the GitHub update check. Release builds moved to 6.12.0 on 2026-11-15, and `scripts/validate_qt_version.py` prints a warning about this CVE for every 6.12.0 build.
  Touches: `scripts/validate_qt_version.py` (6.12 `patched_from` to 6.12.1, drop `pending_fix`, add the CVE to `CVES`, `RECOMMENDED`), `tests/qt_version_policy_test.py`, `SECURITY.md`, README build steps, the Qt default in `scripts/release_windows.cmd` and `scripts/codeql_scan.ps1`, a local `C:\Qt\6.12.1\msvc2022_64` install.
  Acceptance: the validator refuses 6.12.0, passes 6.12.1 with no warning, and the whole test suite passes against 6.12.1.

## P1 Distribution

- [ ] P1 Code signing for Windows and macOS releases
  Blocked on: Matt choosing and paying for a signing identity. Windows needs one of SignPath Foundation (an application in his name), Azure Artifact Signing ($9.99/month, identity validation in his name) or a Certum OV certificate. macOS notarization needs Apple Developer Program enrollment ($99/year).
  Re-tested 2026-11-14: no code-signing certificate in `Cert:\CurrentUser\My` or `Cert:\LocalMachine\My`, and no GPG secret key on the build machine. SignPath Foundation also requires builds to come from a public CI workflow, which conflicts with the repo's local-only release lane, so that route needs his decision too. The checksum half is done: `scripts/release_check.py` writes `release/SHA256SUMS`.
  Why: SmartScreen warns on every unsigned download, and macOS Sequoia removed the Control-click way past Gatekeeper, so an unnotarized DMG needs a trip through System Settings. EV certificates no longer buy instant SmartScreen reputation, and certificate lifetimes are capped at 460 days from 2026-03-01.
  Evidence: azure.microsoft.com/pricing/details/trusted-signing; signpath.org/terms.html; CA/B Forum Code Signing BRs v3.7; developer.apple.com/developer-id
  Acceptance: Windows artifacts are Authenticode-signed with a timestamp and the macOS DMG is notarized and stapled, both from the local release scripts.
  Folded in: the two P2 SignPath entries (application materials and SignPath signing) and the P4 "code signing for releases" entry.

- [ ] P1 Publish a maintainer-owned Homebrew tap
  Blocked on: Matt's word for a release that carries a macOS DMG, and his OK to create the new public repository `SysAdminDoc/homebrew-rclonebrowserng`.
  Re-tested 2026-11-14: Homebrew turned off unsigned casks in the official tap on 2026-09-01, so a third-party tap is the route. The cask is already generated by `scripts/generate_package_manifests.py`. Building the DMG no longer needs a Mac on hand. The hand-started `macos-build.yml` workflow built one on a hosted Mac on 2026-11-15, and the packaged app passed its `--version` smoke test.
  Acceptance: `brew tap SysAdminDoc/rclonebrowserng && brew install --cask rclone-browser-ng` installs the published DMG, the cask's `sha256` matches the release asset, and the README documents the tap and says the build is unsigned.
  Folded in: the P4 "Homebrew formula fix" entry (kapitainsky#232), which was about the old upstream cask that no longer exists.

## P2 Distribution

- [ ] P2 Scoop and AUR packages
  Blocked on: Matt. An AUR package has to be pushed from his AUR account with his SSH key. A Scoop manifest is a hosted install index, which only changes on his word, and it goes either in a bucket repository (a new repo) or in a pull request to ScoopInstaller/Extras under his name.
  Re-tested 2026-11-14: nothing in the repo stops either. winget is dropped for good under the standing rule against creating winget packages, and its generator was removed from `scripts/generate_package_manifests.py` the same day.
  Why: Repology still points people at the dead upstream packages.
  Evidence: repology.org/project/rclone-browser/packages
  Acceptance: `scoop install` and an AUR helper both install the current NG release.

- [ ] P2 Flathub submission
  Blocked on: Matt's decision. Flathub's Generative AI policy (docs.flathub.org/docs/for-app-authors/requirements, read 2026-11-14) requires the submitter to disclose AI-generated code and its extent, forbids AI-assisted content in the manifest, forbids agents from opening the submission pull request, and lets reviewers reject on the extent of generated material. It has no exception for mature projects. Only he can make that disclosure and decide whether to submit.
  Re-tested 2026-11-14: the AppStream metadata now has screenshots and validates with `appstreamcli` 1.0.2, network checks included, so the metadata side is ready.
  Sources: mmozeiko#112

- [ ] P4 Snap Store
  Blocked on: a Snap Store publisher account in Matt's name, which only he can register.
  Re-tested 2026-11-14: snapcraft builds need LXD or Multipass, and the snap name has to be registered to an account before the first upload.
